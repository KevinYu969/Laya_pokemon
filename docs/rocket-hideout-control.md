# 火箭隊基地：箭頭、鑰匙與正常遊戲控制

已正常打贏遊戲中心守衛、回中心補給，2026-10-23台北23:23:35.632412按海報開關進入基地。11段箭頭、電梯鑰匙、月之石、尼多王進化及B4F／B1F電梯均已實測；2026-10-24台北00:15:51.458203觀測坂木勝利文字，00:17:23核對透視鏡入袋。見[整理收據](../results/rocket-hideout-campaign-20261024.json)。四枚徽章，尚未聯盟。

箭頭不由外部逐格重播RLE。控制器只在已核對站位發出一次方向子目標，交本機Laya分類；踏入後由遊戲自行滑行，外部只等待。停止須同時核對預期落點、停止格`0x5E`、移動狀態清零及兩個連續且不同的觀測影格。離開落點即清除穩定樣本，同一影格若位置／旗標矛盾則停止檢討。

唯讀getter在同一影格讀取`CD38`模擬輸入索引、`CD6B`輸入忽略遮罩、`CFC5`步行計數與`D736 bit7`旋轉旗標，前後影格必須一致；未知讀值不以零代替。背景格網另保留真正逐格相等的可見座標、觀測影格及位置，不能填一個合成`verified=true`解鎖。

普通路段沿固定來源路線並避開所有其他箭頭觸發格；滑行期間不累計一般導航卡住次數或學習失敗邊。每段完成有不同的存檔／截圖名稱，避免後一段覆蓋前一段證據。

實戰首段於台北23:38:51.827147核對map201 `(13,11)→(10,11)`；後兩段23:40:23及23:40:24完成。返程亦發現樓梯的來源落點不等於實際走出位置：B4F回B3F後會走到`(19,19)`，不能沿來源起點再踩`(19,18)`樓梯回彈。現在普通路段避開該格，依真實格網接回安全路徑。

鑰匙、透視鏡以背包實際持有判斷，沒有虛構`got_lift_key`或`got_silph_scope`事件；守衛掉鑰匙與已撿取分開，遊戲中心守衛也沒有獨立的beat事件。新增事件首次可讀就為True只算基線，不能杜撰完成時間。

固定來源：[B3F腳本](https://github.com/pret/pokered/blob/a53671100ec22e5394ff26ec028d0812a238dae2/scripts/RocketHideoutB3F.asm)、[B4F腳本](https://github.com/pret/pokered/blob/a53671100ec22e5394ff26ec028d0812a238dae2/scripts/RocketHideoutB4F.asm)、[WRAM宣告](https://github.com/pret/pokered/blob/a53671100ec22e5394ff26ec028d0812a238dae2/ram/wram.asm)、[移動旗標](https://github.com/pret/pokered/blob/a53671100ec22e5394ff26ec028d0812a238dae2/constants/ram_constants.asm)。RAM位置以配置重算及[官方PyBoy 2.8.1常數](https://github.com/Baekalfen/PyBoy/blob/v2.8.1/pyboy/plugins/game_wrapper_pokemon_gen1_constants.py)多個錨點交叉核對；測試用的來源座標／事件資料保存在`tests/data/rocket-source-fixture.json`，不依賴私人輸出或ROM。

## 本輪問題與修正

- **未知畫面不是空白野外。** 獨審重現Window未對齊時被解碼器略過、可能誤啟動或提前完成箭頭的合成反例。現以結構化完整讀取、對齊、Window可見性證據判斷；預設字碼候選警告仍保留。未知落點只wait，必須重新取得兩幀完整野外才完成。
- **樓梯自動走出要用實際位置。** B3F回B2F實際為21,9，不能因來源warp是21,8又立刻踏回去。已移除返程via第一個入口，普通導航避開樓梯格。站在入口未warp時正常離格再進入成功；未證實的「只能從北／DOWN進樓梯」假說已撤回。
- **進化不補錯過招式。** 月石只正常消耗item10一顆，167→7；27級、EXP15999、四招及PP不變，HP73/82→83/92，其餘隊員不變。00:06:55.689197完整姓名intro／成功頁及正常關閉選單一起驗證。返回START會逐列重繪，只有POKéDEX／POKéMON或空心ITEM游標時只有限wait。沒有回補23級Thrash，Nidorino／Nidoking在第一世代也不能學TM28 Dig。
- **電梯動畫與真正抵達分開。** 依完整樓層標籤與實心游標選樓；至少200影格、影子hSCY與硬體rSCY恢復、CHAN5音效清零、可見來源格網及兩幀idle後才正常RIGHT／UP出門。00:13:38.933745實際map202(25,15)才算B4F；00:19:25.526627實際map199(25,19)才算B1F，各有不同存檔名稱。正常warp曾先變map ID、座標仍舊2,1；只有已送正常出口UP的交易可有限wait此過場，不能當抵達證據。
- **唯讀地址須算linker前置段。** 初稿漏算10-byte OAM DMA，hSCY曾誤算FFA5；在實戰接入前已修正**FFAF**。父層獨立下載固定來源重算並核對SHA；另讀FF42與C02A，失敗不補0。
- **戰後補給保留。** 兩守衛事件與四個實際開門格共同核對後才進坂木房。妙蛙草以正常飛葉快刀作戰、升31，戰後52/86HP觸發低血檢討；正常SWITCH健康尼多王28領隊，取鏡後安排回中心，沒有假稱已補血或回讀洗勝負。

1312項完整測試曾通過，其後戰鬥暫交／計時邊界另有188項相關回歸。電梯落地若正常被守衛開戰，保留同一交易並交既有戰鬥控制；已確認的戰鬥期間不耗用電梯60秒上限，calls／waits不重設。未知戰鬥訊號或phase矛盾仍停下檢討。

接續塔內22個唯讀事件整合後，完整回歸已更新為**1406項通過**（一則既有SDL2版本提示）。Tower裸getter沿用上游有效隊伍／已解析背包契約，不代表完整ROM或物種語義校準；可選同幀包裝另有前後frame驗證，不能混成主API本身已證明同幀。
